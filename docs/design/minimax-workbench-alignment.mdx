# 9gLab 用户端 MiniMax Design 工作台对齐基线

> 状态：已确认的实现基线  
> 参考版本：本机 MiniMax Design 3.0.11（冻结，不跟随后续版本）  
> 范围：9gLab 全部正式用户端页面；运营后台不做专项改版  
> 原则：独立实现，只参考可见布局、交互和视觉语言，不复制 MiniMax 源码、品牌、文案或专有素材

## 1. 产品目标

本项目不是单纯换色。目标是在保留 9gLab 现有生成、项目、任务、素材、画布、权限、计费和 API 合同的前提下，将用户端重构为一个“对话驱动创作、画布承载结果、项目组织上下文”的网页工作台。

成功时，用户应形成以下操作心智：

1. 从稳定常驻的侧栏进入创作、项目和能力库。
2. 在首页用一个明确的自然语言输入区开始任务，也可以从案例或已有项目继续。
3. 进入项目后，对话和画布属于同一个工作区；对话负责提出、追问和调整，画布负责组织、查看和继续加工结果。
4. 生成状态、失败、重试、选中、上传和保存都有就地反馈，不要求用户在多个页面之间猜测任务位置。
5. 浅色、深色、桌面和移动端共享同一信息架构，不只是分别做一套皮肤。

## 2. 冻结参考的可见事实

以下内容来自对 MiniMax Design 3.0.11 可见界面的检查，只作为独立实现的设计输入：

- 全局侧栏的可访问宽度为 264px，支持折叠和拖动调整宽度；侧栏内含搜索（`⌘K`）、开始创作、项目库、能力入口、项目分组和账户入口。
- 首页将约 800px 宽的主创作栈放在大面积点阵画布中央：品牌/标题、自然语言输入框、附件/模型/Skill 操作、项目选择、内容标签和媒体案例网格。
- 项目工作台是三段式结构：全局侧栏、可移动到左右两侧的对话栏、无限画布；对话栏和画布之间有可调宽分隔器。
- 画布操作保持悬浮：节点添加、移动/小手、项目资产、帮助、整理、缩放、画布设置、连线和小地图不会挤占内容画布。
- 项目库采用“页面标题与主操作 → 类型标签 → 搜索/排序 → 内容网格”的低装饰布局。
- Skill 与工作流采用“标题与安装/创建操作 → 我的/市场标签 → 搜索与类别筛选 → 大预览卡片网格”的能力市场布局。
- 浅色以接近 `#fafafa` 的画布、白色表面、黑色正文和极浅边界为主；深色以 `#181818` 导航、接近 `#111113` 的工作区和 `#161616` 表面为主。交互强调色使用克制的紫色，建议实现起点为浅色 `#6d6cff`、深色 `#8b8aff`。
- 视觉层级主要依靠留白、表面明度和内容尺度，不依靠大量阴影、渐变或装饰性边框。

这些数值是实现起点，不构成品牌资产，也不要求对不可见实现做逐像素复制。

## 3. 目标布局

### 3.1 首页

```text
┌──────── 264px 可折叠侧栏 ────────┬────────────────────────────────────┐
│ 搜索 / 开始创作                   │                                    │
│ 项目 / 能力入口                   │            9gLab                   │
│ 项目分组与最近项目                │   ┌────────────────────────────┐   │
│                                  │   │ 描述要创作的内容             │   │
│                                  │   │ 附件  模型  能力       发送  │   │
│                                  │   └────────────────────────────┘   │
│                                  │      项目选择 / 最近上下文          │
│                                  │                                    │
│                                  │      类型标签 / 案例媒体网格         │
│ 账户 / 主题 / 设置                │                                    │
└──────────────────────────────────┴────────────────────────────────────┘
```

主内容居中但不做传统营销页 Hero。输入框是唯一强焦点，案例负责提供起点，不与输入框竞争层级。

### 3.2 项目工作台

```text
┌──── 全局侧栏 ────┬──────────── 无限画布 ────────────┬──── 对话栏 ────┐
│ 项目与创作页       │  悬浮画布工具                     │ 新建对话        │
│ 最近项目           │                                  │ 消息/案例/结果   │
│                    │        节点、媒体、分组与连线       │                 │
│                    │                                  │                 │
│ 账户               │  整理 / 缩放 / 小地图             │ 输入与生成操作   │
└───────────────────┴──────────────────────────────────┴───────────────┘
                        可调宽分隔器；对话可切换左右侧
```

9gLab 继续使用现有 `InfiniteCanvas`、`CanvasAssistantPanel`、任务状态、画布工具、缩放和小地图；实现重点是把这些能力组合进统一项目工作台，而不是重写画布引擎。

### 3.3 移动端

MiniMax Design 参考产品是桌面应用，因此移动端不声称逐像素复制。移动端遵循同一操作模型，并作网页端独立适配：

```text
┌──────────────────────┐
│ 菜单  项目名   更多    │
├──────────────────────┤
│                      │
│   对话 或 画布主区域   │
│                      │
├──────────────────────┤
│  对话   画布   任务    │
└──────────────────────┘
```

- 全局侧栏改为抽屉，不压缩主内容。
- 对话与画布改为互斥主视图，可通过底部/顶部模式切换进入；不能在窄屏强行并排。
- 输入区吸底并避让安全区；画布工具缩为单列/分组悬浮控件。
- 关键操作不依赖 hover，所有图标操作有可访问名称和至少 44px 的移动端命中区。

## 4. 视觉令牌起点

| 角色 | 浅色 | 深色 | 使用规则 |
| --- | --- | --- | --- |
| 全局画布 | `#fafafa` | `#111113` | 页面与无限画布的底层 |
| 导航表面 | `#f4f4f6` | `#181818` | 与主区保持小幅明度差 |
| 内容表面 | `#ffffff` | `#161616` | 输入框、浮层、卡片、面板 |
| 主文字 | `#000000` | `#e0e0e0` | 正文和高优先级图标；暗色卡片标题可使用 `#fafafa` |
| 次级文字 | `#00000080` | `#ffffff99` | 说明和元数据 |
| 三级文字 | `#00000052` | `#ffffff6b` | 占位、弱提示和低优先级元数据 |
| 边界 | `rgba(0,0,0,.08)` | `rgba(255,255,255,.10)` | 只用于需要结构分隔的位置 |
| 强调 | `#6d6cff` | `#8b8aff` | 主操作、焦点、任务进行态 |
| 选中底 | `rgba(109,108,255,.10)` | `rgba(139,138,255,.16)` | 导航/筛选选中，不代替文字状态 |

组件起点：导航行 40px、桌面常规控件 32–36px、移动端关键控件 44px、输入框大圆角 20–24px、媒体卡片 12px、菜单/普通输入 8px。动效集中在折叠、面板切换、发送反馈和任务状态，时长以 120–240ms 为主，并尊重 `prefers-reduced-motion`。

### 4.1 字体合同

MiniMax Design 3.0.11 的运行包不是“全站一套 Inter”，而是三层字体：

| 角色 | 字体 | 字重 | 使用范围 |
| --- | --- | --- | --- |
| 应用 UI | `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", sans-serif` | 400 / 500 / 600 / 700 | 导航、按钮、表单、普通正文；中文由系统字体回退，macOS 实际命中苹方 |
| 内容正文 | `Inter Variable, sans-serif` | 100–900 可变，产品仅使用 400 / 500 / 600 / 700 | 对话内容、工具结果和显式 `font-sans` 内容 |
| 标题 | `Outfit, sans-serif` | 400 / 600 | 页面标题、弹窗标题、重要数字和标题型控件 |
| 装饰字体 | `Pixelify Sans, Outfit, sans-serif` | 400 | 少量像素风品牌装饰，不用于普通正文 |
| 代码 | `ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, "Liberation Mono", "Courier New", monospace` | 400 / 500 | 代码、参数和机器可读内容 |

`Noto Sans CJK SC Regular` 虽随参考应用安装，但其说明文件明确标注为 FFmpeg 字幕渲染的确定性回退，不是工作台 UI 字体，因此不用于 9gLab 页面。

核心字号与行高冻结为：

| 角色 | 字号 / 行高 |
| --- | --- |
| 微型说明 | 10 / 14px |
| 标签 | 11 / 16px |
| 辅助正文 | 12 / 18px |
| 紧凑正文 | 13 / 20px |
| 默认正文 | 14 / 22px |
| 大正文 | 15 / 23px |
| 首页输入 | 15 / 22px |
| 首页输入工具栏 | 14 / 22px |
| 首页副标题 | 16 / 24px |
| 首页展示标题 | 40 / 40px |

字重只能使用 400、500、600、700。9gLab 原有 450、520、560、620、650、680、720 等中间值统一归并到最近的参考档位，防止不同系统字体对非标准字重做出不一致的合成结果。正文默认不额外加字距；对话输入允许 `-0.01em`，工具栏使用 `-0.52px`，中文首页副标题使用 `0.08em`，英文使用 `0.04em`。

## 5. 9gLab 路由覆盖矩阵

| 路由/状态 | 当前职责 | 对齐参考 | 实施策略 | 优先级 |
| --- | --- | --- | --- | --- |
| `/`、`/create` | 创建入口、对话、分镜结果 | MiniMax 首页 | 保留现有生成和分镜状态；重排为中央输入栈、项目上下文和案例区 | P0 |
| `/canvas/:id` | 无限画布编辑器 | MiniMax 项目工作台 | 恢复全局侧栏；组合现有对话面板与画布，增加桌面可调分栏和左右布局 | P0 |
| `/projects/:projectId*` | 项目、章节、工作流 | MiniMax 项目工作台 | 维持路由和数据；统一工作台顶栏、上下文导航和阶段状态 | P0 |
| `/projects` | 短剧项目库 | MiniMax 项目库 | 使用标题/主操作、筛选、搜索、排序和低装饰项目网格 | P1 |
| `/canvas` | 画布项目库 | MiniMax 项目库 | 与项目库共享页面骨架和集合卡片合同 | P1 |
| `/assets` | 素材库 | 项目库 + 项目资产面板 | 保留分类、回收站、批量操作和预览；统一筛选栏、网格与详情抽屉 | P1 |
| `/tasks` | 生成任务中心 | 工作流列表 + 工作台任务状态 | 保留任务数据；强调进行中、失败、重试和结果回到项目/画布 | P1 |
| `/skills` | Skill 市场与管理 | MiniMax Skill | 标题/创建安装、市场/我的、搜索/分类、大预览网格 | P1 |
| `/plugins`、`/plugins/eagle` | 插件与素材连接 | MiniMax Skill/工作流 | 复用能力库骨架；插件连接状态作为卡片的主要状态 | P1 |
| `/wallet` | 余额、兑换、流水 | 账户菜单 + 设置 | 不仿造不存在的 MiniMax 页面；沿用低装饰设置页语言和清晰数据层级 | P2 |
| `/settings` | 账户、主题、模型等设置 | 账户菜单 + 设置入口 | 保留左侧设置分区；收敛控件、说明和保存反馈 | P2 |
| `/login`、`/register`、`/forgot-password` | 身份入口 | 全站低干扰语言 | 移除当前电影海报式双栏主导；使用安静画布、单一身份卡和站点品牌 | P1 |
| `/share/canvas/:token` | 公开画布查看 | 画布展示模式 | 保留公开访问；隐藏创作型复杂控件，使用同一画布视觉和轻量顶栏 | P2 |
| `RequireFeature` | 功能未开放 | 空/禁用状态 | 在原页面骨架内解释状态和可执行下一步，不形成突兀独立页 | P2 |
| 路由懒加载 | 打开页面/创作空间 | 工作台加载反馈 | 骨架与主布局一致，避免全屏品牌动画造成上下文跳变 | P2 |
| 错误页、404、数据空态 | 异常和无内容 | 全站状态语言 | 说明发生什么、用户能做什么；提供明确返回或重试操作 | P2 |
| `/test-voice-recording` | 内部验证 | 无正式参考 | 只承接全局主题，不做专项视觉验收 | Internal |
| `/dev/*` | 开发实验室 | 无 | 不进入生产改版范围 | Excluded |
| `/admin/*` | 运营后台 | 无 | 不专项改版；只做全局主题影响后的可读性和关键操作冒烟 | Excluded |

`/projects/:projectId*` 包括项目主页、`:view`、章节页和工作流阶段页。所有正式用户路由都必须覆盖加载、空、正常、失败和无权限/功能关闭状态。

## 7. 代码映射与复用边界

| 现有实现 | 复用方式 | 需要修改的原因 |
| --- | --- | --- |
| `AppWorkspaceShell`、`WorkspaceSidebarNav`、`WorkspaceCommandPalette` | 保留结构、路由和 `⌘K` 行为 | 侧栏改为 264px、项目上下文重组；具体画布页不再完全隐藏全局壳层 |
| `skin-themes.ts`、`AppProviders`、Ant Design token 桥接 | 作为全站浅/深主题唯一入口 | 增加/调整 Studio Canvas 语义值，避免页面硬编码绕过后台主题 |
| `CreatePage` | 保留请求、对话、附件、模型、分镜状态 | 重新组织首页/线程布局，不改变生成逻辑 |
| `InfiniteCanvas`、`CanvasAssistantPanel`、画布工具、缩放、小地图 | 原样优先复用 | 调整容器和分栏，不重写画布算法 |
| `WorkspacePage`、集合网格和库页面 | 共享项目库/素材库/能力库骨架 | 收敛标题、筛选、搜索、卡片和空态层级 |
| 现有登录/注册逻辑 | 完整保留 | 只替换电影海报式视觉容器和响应式布局 |

当前实现存在两个明确的前置风险：

1. `AppWorkspaceShell` 对 `/canvas/:id` 使用 `hideChrome`，这与统一工作台目标直接冲突，需要修改前端布局合同。
2. `globals.css` 中 `.creation-home` 根规则存在多个后置声明区（当前至少位于约 9807 和 13160 行），实现前必须先收敛或明确层级，避免后写规则静默覆盖新设计。

## 8. 设计自检

本方案刻意避免把 9gLab 做成通用 SaaS 卡片后台：

- 不使用营销式渐变 Hero、成排同构统计卡或装饰性标签。
- 只把“自然语言创作输入 + 对话/画布一体工作区”作为强记忆点，其余页面保持安静。
- 不把所有内容都包进带阴影圆角卡片；页面层级优先由尺度、留白和明度表达。
- 不复制 MiniMax 品牌视觉；9gLab 的产品名、功能名、案例内容和媒体资产保持独立。

初步方案曾把重点放在“主题换肤和卡片统一”上；本基线已修正为“操作模型优先、主题作为支撑”。后续评审首先检查用户能否自然完成“开始创作 → 进入项目 → 对话调整 → 画布整理 → 回看任务/资产”的连续流程，其次才检查单页像素相似度。

## 9. 实施顺序与完成定义

1. 全站主题基础：令牌、浅深模式、字体尺度、圆角、边界、动效和第三方控件桥接。
2. 全局壳层：264px 侧栏、项目列表、命令搜索、账户区、移动抽屉。
3. 核心创作：创建首页和 `/canvas/:id` 对话/画布工作台。
4. 用户路由批次：项目/画布库 → 资产/任务 → Skill/插件 → 账户/认证/分享/异常。
5. 视觉回归和功能回归：逐路由、逐主题、逐断点验收。

完成必须同时满足：

- 用户现有功能、路由、权限和 API 合同没有因视觉改版丢失。
- 所有正式用户路由都有浅色、深色和移动端可用布局。
- 核心创作流程在桌面呈现对话/画布一体工作区，在移动端提供明确模式切换。
- 管理端虽不专项对齐，但在全局主题下仍可读、可导航、可保存。
- 不包含 MiniMax 源码、品牌标识、文案或专有素材。
